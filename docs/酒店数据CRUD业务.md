实现后端的酒店数据的录入、审核、修改、查询、软删除业务。

粗粒度的业务需求如下：

## 商家

1. 商家登录
  - 商家登录后，进入酒店列表
2. 酒店列表中，可以创建酒店
  - 只需要商家输入酒店昵称即可（仅商家可见，方便商家区分和管理不同的酒店）
  - 删除酒店按钮，将酒店`已删除`设置为真，将不能被查询到。
3. 点击某个已创建的酒店，进入酒店管理页面
  - 当前发布的酒店信息（关联的已发布的酒店信息 Object|null
  - 开启首页广告推送 Boolean（默认false）
  - 酒店信息列表：
  - 创建酒店信息按钮（进入编辑页面）
    - 让商家填写表单内容...
    - 创建之后，酒店信息状态默认为 `待发布`状态
  - 在酒店信息管理列表中：
  - 商家可手动点击某一条状态为`待发布`或者`待更改`的酒店信息，点击按钮**发布**，此时酒店信息变化为`审核中`状态
  - 如果**审核通过成功**，则该条酒店信息状态变为`已发布`。并且将酒店关联的已发布的酒店信息关联到这一条酒店信息
    - **审核通过时**，酒店之前存在已发布的酒店信息，在关联新的"已发布的酒店信息"时，将`旧的已发布的酒店信息`设置为`待发布`。
  - 若**审核失败**，则该条酒店信息状态变为`待更改`。处于该状态下的酒店信息的编辑页面时，会在上方额外显示审核失败的原因。
  - 商家可对`审核中`的酒店信息进行**撤回**操作。撤回操作后，酒店信息状态变为`待发布`。
  - 商家可对`已发布`的酒店信息进行**下线**操作。下线操作后，酒店信息状态变为`待发布`，同时也会与酒店的"已发布的酒店信息"解除关联。
  - `已发布`,`审核中`的酒店信息不能编辑。
  - 所有的酒店信息都可以进行**创建副本**操作，这将会产生一条新的酒店信息，新的酒店信息状态为`待发布`，信息昵称为`原酒店信息信息昵称-副本`。
  - 所有的酒店信息都可以进行**删除**操作，删除操作后，酒店信息状态变为"已删除"，将不能被任何人查询到。

## 管理员

1. 管理员登录
2. 进入审核页面
  - 信息列表页面（可筛选：待审核（审核中）、已通过（已发布）、已拒绝（待更改））
    - 注意：待审核，是管理员的视角，`审核中`才是酒店信息真正的状态，已通过、已拒绝也是同理，因为视角不同，所以前端展示的名称不同。
    - 点击某一条即可进入信息查看与审核表单的页面。展示酒店信息，填写审核记录
    - 合法的状态转移操作：待审核 -> 已通过、待审核 -> 已拒绝、已拒绝 -> 已通过（仅针对已拒绝的酒店信息）、已通过 -> 已拒绝（仅针对已发布的酒店信息）
    - 审核记录：包含：审核时间、审核人、审核结果、审核原因（必选）、审核备注（如果审核原因不是`其他`，则该项可选）  
  - 审核记录页面
    - 筛选条件
      - 审核时间（start, end, desc/asc）
      - 审核结果（select）
      - 审核原因（select）
    - 按筛选展示审核信息列表
    - 点击某一条即可进入信息查看与审核表单的页面。

## 酒店主要信息举例

- 信息昵称（仅商家可见，方便商家管理不同的酒店信息）
- 酒店名称 String
- 酒店英文名称 String
- 酒店地址（省）String
- 酒店地址（市）String
- 酒店地址（区）String
- 酒店详细地址(xx省xx市xx区xx街道xx号，这种) String
- 酒店地理位置（PostGIS定位）
- 酒店星级（int 1-5）
- 酒店标签（String[]，例如停车场、豪华、亲子）
- 酒店简介 String
- 详情页顶部轮播图（需要提供图片链接、图标描述）
- 房型列表（包含：房型名称（房型类型），计价方式（按小时、按夜晚），价格，入住人数，房间面积，床型说明，参考图片，扩展描述）
- 首页广告图 String （图片链接即可）
